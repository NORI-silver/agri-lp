# [A] 農産物マッチング UI/UX 再設計

目的：閲覧開始から「相談先を選ぶ」までを短くし、比較・相談を独立した操作として分かりやすくする。

## 観察した問題

- トップに長い入力フォーム、対象者別入口、結果、説明、ECサンプルが縦積み。主要な操作の優先度が曖昧。
- 説明と注意書きがカードや画面で重複し、農産物を探す楽しさと候補の違いが見えにくい。
- 比較は同一ページのDOM差し替えで戻る操作とURLが一致しない。比較選択後の次の操作も離れていた。
- 図形イラストと同じ大きさの緑の箱が続き、写真・文字・余白に強弱がない。

## 新しい構成

- `/`：写真を使った導入、品目/キーワードの短い検索、カテゴリー、公式情報の参照先、利用の流れ。詳細フォームを置かない。
- `/producers/`：検索・品目/利用目的/農園所在地の絞り込み。カードの概要と詳細ダイアログ。公式情報の根拠は詳細で確認できる。
- `/match/`：用途と品目→必要な取引条件→候補確認、の3段階。必須は用途と分類のみ。詳細条件は未定でも進める。
- `/compare/`：選択した最大3件を同じ項目で比較。未確認を適合に変えない。モバイルは比較表の内部だけ横スクロール。
- `/inquiry/`：相談文の編集・コピー/保存と、選んだ公式窓口。サイト内送信と誤認しない文言。
- `/requests/`：端末に保存した未送信の下書き。
- `/how-it-works/`：実際に使える機能と相談の流れ。
- ECは補助導線として維持。修理ページの内容とURLは保持。

## 見た目と操作

- 深い緑・白・温かいグレーを基本とし、主CTAを明確にする。大見出しは明朝、操作部分は読みやすいゴシック。
- オリジナルの農産物イメージ写真を生成して使う。実在する参照先や販売商品の写真としては使わず、生成画像であることを表示。
- 比較選択時だけ比較バーを表示。モバイルのナビゲーションと干渉しない余白を確保。
- ネイティブダイアログ、ラジオボタン、ラベル、キーボード操作、フォーカス表示、読み上げ用ステータスを維持。
- 機能の制限は行動する地点で簡潔に伝え、同じ注意文を繰り返さない。

## 実装・検証の記録

- 従来トップの詳細フォームは10項目（ページ全体では比較チェック4個を含め入力コントロール14個）。新トップの検索は用途・キーワードの2項目。詳細入力は別ページへ移動した。
- トップの写真と検索は生成HTMLにも含め、データ読込前から表示。CSS/JSには内容ハッシュを付け、公開後の古い表示を抑える。
- 360/390/768/1280pxを確認。写真の高さと見出しの折り返し、1件比較の不要な横スクロールを目視で修正。3件比較では表の内側のみスクロールする。
- ローカル操作テスト：検索・用途/品目絞り込み・詳細ダイアログ・Escape・比較選択の再読込保持/上限・3段階入力の戻る/再読込/入力エラー・比較/相談ページ・コピー/ダウンロード/下書きの重複防止/削除・未確認の扱い・XSS文字列・画像の読込を確認。
- 既存EC/注文API、注文データ単体5件、SEOチェックも成功。外部の生産者への自動送信・契約・課金は行っていない。
