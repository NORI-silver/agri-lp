# SEO Agent（機械修理さがし / agri.shiokonbu.com）

目的は **小型機械・作業機（農業機械も含む）の実際の修理業者への接続**。現行方針は `docs/strategy.md` v0.2。千葉県×草刈機・刈払機を最初に検証し、A：業者探索を優先する。PV目的の記事は作らない。
従来の通常SEO作業は自動マージ方針だったが、2026-11-03の転換指示を優先する。**転換設計・PoCのPRはmainにマージしない。ユーザーから次の指示があるまで自動マージ対象から除外する。** 追加の全ページ更新指示により、PR #8はトップ・全既存記事・共通表示まで更新するが、マージ保留は継続する。設計書のその他の将来案を実装許可と解釈しない。

## 動かし方

- 定期タスク「agri SEO 毎日チェック」（毎日1回）がこの手順で動く。利用上限はアカウント全体で共有なので、読むものは最小限に。
- 読むのは `AGENTS.md`・このファイル・`docs/seo-log.md` の最後の10行だけ（ほかは必要なときだけ）。

## 1回の手順

1. `main` を取り込む。開いているPRの対象と保留指示を確認する。転換・PoCのPRはチェックが緑でもマージしない。他のPRも個別の最新指示を優先する。
2. 公開の確認：最新の main が GitHub Pages に出ているか（Actions の pages の結果）。止まっていたら原因を調べて直す。
3. `python3 tools/seo_check.py .` の NG があれば最優先で直す。
4. Search Console の数字（1日1回まで）：プロパティ `https://agri.shiokonbu.com/`。読み方は pet と同じく Nori さんの Mac の Remote Control で読むだけ（クエリ・ページ別、直近7日と28日）。数字が出ていなければ推測しない。変化を seo-log に1行。
5. 改善は **1回に1つだけ**。優先順：
   1. 草刈機・刈払機の修理業者DB原本・受付条件の不足を確認し、公式情報で埋める（内部情報は公開しない、事業者への連絡は明示の依頼が必要）
   2. 条件が分かる業者への問い合わせ導線と結果計測を整える。クリックと実問い合わせ・実依頼を区別する
   3. `docs/keyword-map.md`で重点KWの受けページと検索意図の不足を確認し、供給・料金・監修の根拠が揃った範囲で改善する
   4. そのうえでGSCの表示・CTR・順位とインデックス状況に基づき、既存ページを改善する。数字がなければ推測しない
6. 元ファイル（`tools/pages.py`）を直し、`python3 tools/build.py .` → `python3 tools/seo_check.py .`。
7. `main` からブランチ `claude/seo-<日付>-<短い名前>` を切ってPR（本文の頭に [B]）。`docs/seo-log.md` に1行。転換・PoCのPRは未マージで報告する。通常SEOのマージは最新の個別指示と競合しない場合に限り、公開まで確認する。
8. 報告は転換・PoCのPR作成時、マージして公開を確かめたとき、または Nori さんの手が要るときに、1〜2行。直すことがない回は何もしない（ログも書かない）。

## 守ること（AGENTS.md の要点）

- 数字・事実は公式サイト・公式の料金表で確かめたものだけ。出典（`SOURCES`）と確認日を付ける。
- サイト上に「shiokonbu」を出さない。サイト名は「機械修理さがし」。
- 症状ページ（自分で確かめる手順）は整備士の監修が取れるまで作らない。
- 市町村ページは確認済み事業者3社以上、県ページは10社以上になるまで作らない。
- 事業者への連絡はしない。根拠のない売り文句（24時間・即日・No.1 など）は書かない。
- 大きな作り替え・新しい種類のページは、まず seo-log に案を書いて次回以降に。

## 転換中の優先事項

- agri-lpを最優先。wheelchair-lpと両方に作業候補があれば原則agriを先に進める。wheelchairは既存SEOの効果測定と最低限の保守を優先し、大きな追加実装は後回し。ここから他リポジトリを変更しない。
- DB原本・実スキーマは未確認。`tools/pages.py` の32拠点集計を対応可能業者数としない。原本確認と機種・購入経路・運搬条件の検証を先に行う。
- 事業者への連絡は明示の依頼を受けるまで行わない。地域ページの既存公開基準を維持する。
- 電話・サイト遷移・問い合わせ・実依頼・問い合わせ可能数・実対応可能数を別々に評価。GA4クリックは依頼完了の代用にしない。
- 新カテゴリや症状ページの量産をせず、まず既存草刈機ページと供給条件の不足を改善する。
